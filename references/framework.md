# Quill 四文件架构

> 本文档在用户询问"四文件架构是什么""为什么是四个文件"时加载。

## 为什么需要结构

长文写作的失败，绝大多数不是"没东西可写"，而是"材料丰富却理不清"。
人脑能同时持有的工作记忆容量极小；当论点、证据、读者、风格四件事同时占用心智，写作就会卡住或跑题。

Quill 的解法：把这四件事从大脑里"卸载"到四个独立文件中。每个文件只回答一个问题，互相不耦合，但通过 `_index.md` 互相关联。

## 四个文件各回答什么

| 文件 | 只回答的问题 | 完成的标志 |
|------|------------|----------|
| `claim.md` | 这篇文章最想传递什么？ | 一句话核心论点 + 3-5 条支撑要点 |
| `evidence.md` | 我凭什么这么说？ | 每条证据有来源、可信度、链接 |
| `audience.md` | 我在对谁说？他读前读后有何不同？ | 读前状态 + 读后状态 |
| `style.md` | 用什么语气和结构来说？ | 语调、开篇钩子、隐喻、结尾 |

## 完整文件结构（文件边界）

四文件是思维标本的骨架，但一个文章项目实际有七个文件，分两类：

**Agent 读写**（模型的工作区）：
- `_index.md` — 文章入口 + 状态 checklist
- `claim.md` / `evidence.md` / `audience.md` / `style.md` — 四文件骨架
- `ai-draft.md` — Agent 按自己的理解写出的**完整草稿**（成篇文章 + 起草说明 + 对你草稿的建议 + 反驳记录）

**用户读写、Agent 只读**（用户的最终文章）：
- 用户的草稿（文件名不限，默认 `draft.md`）— 由用户自己写作；Agent 只读不写，无论它叫什么名字。

**边界规则**：Agent 只在自己创建的项目文件夹内读写；Agent 按自己的理解写出完整草稿放进 `ai-draft.md`，由用户决定是否采纳进自己的草稿。这条边界保护"人类始终保留最终写作权"——Agent 可以写出完整的一版，但不能替用户定稿。

## 顺序不是线性的

四文件不是严格的"步骤 1→4"，而是一个可回溯的循环：

- 写草稿时发现证据不够 → 回到 `evidence.md` 补证据；
- 发现某段写不动 → 往往是 `claim.md` 的论点太宽，回去收窄；
- 风格跑偏 → 对照 `style.md` 拉回。

`_index.md` 的 checklist 就是为了让这个回溯可见、可追踪。

## 与传统大纲的区别

传统大纲把"论点—证据—结构"塞在一个文件里，三者纠缠，改一处牵动全局。
Quill 把它们拆开：改论点只动 `claim.md`，补证据只动 `evidence.md`，结构选择（先讲什么后讲什么）留到草稿里即兴决定。
代价是多几个文件；收益是每个文件都短、独立、可独立核查——这正是"可验证、可追溯"的来源。

## 模型驱动（无脚本）

四个文件的创建、互查、汇总都由模型自身读写与判断完成，不调用任何脚本。
这与作者知识库 AGENTS.md 的红线一致：禁止脚本批量修改笔记，读取 > 建议 > 手动修改。
