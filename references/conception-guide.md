# 构思引导（结构化提问）

> 本文件在第二步（构思引导）时加载。描述如何用结构化提问工具引导用户从模糊意图走到具体方向。
> 核心原则：空白模板让人卡住；具体选项让人选择。构思阶段的敌人不是"没想法"，而是"想法太多理不清"。

## 提问工具适配

不同 harness 的多选提问工具不同：

| Harness | 提问工具 | 能力 |
|---------|---------|------|
| DSH | `ask_user_question` | 多问题 + 选项 + 推荐 + 单/多选 |
| Codex | 等价多选提问 | 多选项 + 用户选择 |
| Claude Code | 等价多选提问 | 多选项 + 用户选择 |
| OpenCode | 等价多选提问 | 多选项 + 用户选择 |
| Obsidian Agent Client | ACP 协议提问 | 多选项 + 用户选择 |
| 无提问工具 | 纯文本列举 | "请在 A/B/C 中选择，或补充你的" |

> 检测到提问工具时优先用之；没有则用纯文本模拟（列出编号选项 + "或自行补充"）。环境探测见 `references/environment-detection.md`。

## 说话位置（构思前内部五问）

> 这五问在构思引导前先在内部回答。不要把问题清单抛给用户——你的回答是内部判断，不是输出。

动笔前回答五件事：

1. **谁在说这件事？** 他凭什么知道，又有哪些地方只是在推测？
2. **什么事情让他现在想说？** 可以是一条新闻、一次经历、一个疑问或一件一直想不通的小事。
3. **手里有哪些能托住文章的东西？** 优先找动作、数字、时间、地点、原话、失败、代价与后来结果。
4. **他对哪一点有明确判断？** 这个判断依据什么，又到哪里为止？
5. **读者知道上一段以后，最自然会追问什么？**

第 3 项太少 → 回到材料清点（第一步半）。不要用哲理、象征、想象现场和重复结论补字数。

> 这一问不是让你把答案原样交给用户。你的回答应该让后面三轮提问的选项更有针对性——论点候选更具体、读者画像更贴合、语调选项更精确。

## 三轮提问设计

### 第一轮 — 定方向（一次调用 3 个问题）

**Q1 文章类型**（单选，4 选项）：

| 选项 | 描述 |
|------|------|
| 观点论述 | 对某话题提出明确立场并用证据支撑 |
| 经验分享 | 从亲身经历中提炼可复用方法或教训 |
| 技术解析 | 拆解一个技术/工具/概念，让读者能用起来 |
| 趋势分析 | 识别正在发生的变化，判断走向与影响 |

**Q2 核心论点方向**（单选，2-4 选项）：

模型根据用户写作意图提出 2-4 个具体论点候选。每个候选：
- 一句话论点（具体、可反驳、有立场）
- 一句话适用场景
- 标注推荐项（放第一位 + "(推荐)"）

> 例：用户说"想写 AI 与设计"，模型提：
> A(推荐)：AI 不会取代设计师，但会重设其工作——判断标准由人定义
> B：设计系统是 AI 时代的护栏，不是协作工具
> C：设计师的新护城河是"定义约束"而非"产出像素"

**Q3 论证类型**（单选，3 选项）：

| 选项 | 描述 |
|------|------|
| 事实主张 | 是什么——用数据/证据证明某事为真 |
| 价值主张 | 应该怎样——论证某事值得/不值得 |
| 政策主张 | 该做什么——提出具体行动建议 |

### 第二轮 — 定读者（一次调用 2 个问题）

**Q4 读者画像**（单选，2-3 选项）：

模型提出 2-3 个读者画像候选。每个画像含：
- 认知水平（入门 / 有经验 / 决策者）
- 痛点（他现在卡在哪）

> 例：A(推荐)：用 Figma 做设计系统、但没用过 AI 辅助的设计师——怕被替代
> B：设计团队 lead——需要决定要不要引入 AI 工具链

**Q5 读者读前状态**（单选，3 选项）：

针对选定的画像，提出"他现在相信什么"：

| 选项 | 描述 |
|------|------|
| 误解 | 他信了错的（如"AI 会画图=设计师没了"） |
| 盲区 | 他不知道的（如设计系统在 AI 生成中的地基作用） |
| 情感 | 他焦虑/抵触的（如担心职业价值被稀释） |

### 第三轮 — 定风格（一次调用 3 个问题）

**Q6 语调**（单选，3 选项）：

| 选项 | 描述 |
|------|------|
| 直接克制(推荐) | 短句、主动语态、少形容词、第一人称判断 |
| 带调侃 | 克制底色 + 适度自嘲/反讽拉近距离 |
| 严肃论证 | 逻辑链密、证据密集、语气庄重 |

**Q7 开篇钩子**（单选，4 选项）：

模型根据论点推荐一种钩子类型（标注推荐项）：

| 选项 | 描述 |
|------|------|
| 问题 | 抛一个读者答不上来的问题 |
| 场景 | 一个具体时刻/画面 |
| 数据 | 一个反直觉的数字 |
| 引用 | 一句值得反驳的权威话 |

**Q8 结尾动作**（单选，3 选项）：

| 选项 | 描述 |
|------|------|
| 纯收束(推荐) | 最小可交付 / 可执行动作 |
| 引导评论 | 抛一个开放问题邀请讨论 |
| 引导订阅 | 预告下一篇 / 系列入口 |

## 选项设计原则

- **具体优于抽象**：不提"专业读者"，提"用 Figma 做设计系统、但没用过 AI 辅助的设计师"。
- **推荐项标注**：放第一位 + "(推荐)"，给用户一个默认路径。
- **允许补充**：每个问题都允许用户选"其他/自行补充"。
- **不超过 4 选项**：超过 4 个认知负荷过大。
- **选项有描述**：每个选项一句话说明 tradeoff 或适用场景。
- **选项从用户语料来**：论点候选优先从本地知识库 / cgartlab.com 历史文章 / github.com/cgartlab 抽取，不凭空生成。

## 答案去向

三轮答完后：

| 答案 | 去向 |
|------|------|
| Q1 文章类型 + Q2 论点 + Q3 论证类型 | → 预填 `claim.md`（核心论点 + 支撑要点 + 论证类型） |
| Q4 读者画像 + Q5 读前状态 | → 预填 `audience.md`（读前状态 + 读后状态） |
| Q6 语调 + Q7 开篇钩子 + Q8 结尾动作 | → 预填 `style.md`（语调 + 开篇钩子 + 结尾动作） |

预填后进入第三步（定义核心论点），用户在已填的基础上精修，而不是从零写。

## 与碎片化写作的关系

构思引导是"捡骨头"之前的定向环节——先用提问把方向锁定，再进入 writing-craft.md 的碎片化写作四步。构思引导产出的是骨架的初稿，碎片化写作产出的是血肉。
