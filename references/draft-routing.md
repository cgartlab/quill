# 按草稿状态分流

> 本文件在**第一步判读草稿状态之后**加载。三种情形走三条不同的路，但**最后都汇进同一条主干**（论点 → 证据 → 受众 → 风格 → 写作 → 反驳 → 验证）。

## 先判读状态

扫文章项目文件夹，看用户手里已经有什么：

| 情形 | 判据 | 走哪条 |
|------|------|--------|
| **A 没有草稿** | 项目文件夹里没有用户的文章文件，用户也没给正文 | A 线：先讨论出主题 |
| **B 有部分草稿** | 有正文，但缺段、缺结尾、逻辑没理顺、或只是零散段落 | B 线：先理顺再加厚 |
| **C 有完整草稿或大纲** | 有完整成稿，或有一份成形的大纲 | C 线：直接补全与加固 |

**判不准就问。** 拿不准属于 B 还是 C，直接把两边的差别说给用户听，让他定——**不要替他归类**。用户说"我有一份草稿"但你没找到文件时，问他要，不要当作 A。

---

## A 线：没有草稿 → 先讨论出核心主题

不要一上来就问"你想写什么"——那等于把空白模板丢回去。按这个顺序走：

1. **请用户给料**：让他随便说——最近在想什么、碰到过什么事、哪件事他憋着想说。**允许他杂乱地说，这一步不要求成句。**
2. **顺着他的料讨论**：把你的理解说出来（"所以你其实是想说 X？"），让他纠。**反复到你们对"这篇文章到底要说什么"没有分歧为止。**
3. **得出核心主题**：一句话说清"这篇文章是关于什么的"，请他确认。
4. **围绕主题问核心疑问**（见 `references/conception-guide.md`「核心疑问」）：
   - 写这个主题的**由来**是什么？
   - **哪些人**会对这个主题感兴趣？
   - **亲身经历**是什么？**有没有细节**？
   - 文章最终会发布到**什么平台**？
   - 其余问题**你按这个主题的具体情况补**（例如：有没有反方观点？有没有一次失败？时间上急不急？）
5. **进入共用主干**（第三步起）。

> **由来问不出来，文章就没有理由存在。** 用户答不出"为什么现在写这个"，就先别往下走——缺的环节要问清楚（见文末）。

## B 线：有部分草稿 → 先理顺，再加厚

**顺序不能颠倒**：没理顺逻辑就补内容，等于往歪的骨架上挂肉。

1. **分析行文逻辑**：读他的草稿，把现有的推进线画出来——每一段在干什么？主张是什么？哪几段其实在说同一件事？哪里断了？
   - 产出：一份**逻辑诊断**（现有主线 / 重复处 / 跳跃处 / 缺失的环节）。
   - **先只诊断，不改稿**（与第八步同一纪律）。
2. **梳理并补全大纲**：在诊断基础上给出补全后的大纲，标清楚**哪些是原有、哪些是你建议新增**。请他确认后再动。
3. **写出你的草稿**：按确认的大纲，写进 `ai-draft.md`（**绝不改用户的草稿**）。他原有的话尽量保留——那是他的声音。
4. **去掉 AI 的味道**：走校订期流程（`references/style-and-bans.md` + 六遍改稿）。**他草稿里原本就没有 AI 味的段落，不要"顺手改好"**。

## C 线：有完整草稿或大纲 → 直接补全与加固

1. **直接补充完整内容**：
   - 给的是**大纲** → 把内容补成完整文章，补写部分标出来源或用缺口标记。
   - 给的是**成稿** → 补它缺的（论证漏洞、缺失的反方、没有落地的结尾），**不要重写他写对的部分**。
2. **给出更多真实可靠的案例建议**：针对他的论点，主动提**能查到的**案例、数据、反面例子。
   - **每条建议都要带真实链接**；查不到就明说"这条我没找到可靠来源"，**不要**递给一个像真的例子。
   - 案例建议交给他决定用不用——**最终取舍是他的**（见第四步）。
3. **去掉 AI 的味道**：同 B 线第 4 点。

---

## 三条线共用的纪律

- **不确定作者意图，必须问。** 任何一步你猜他要什么、猜某段该不该留、猜他认可不认可某个立场——**停下来问**。猜错的代价是他要通读一遍推翻重来。
- **缺必要环节，必须问要不要补。** 发现少了"由来 / 受众 / 亲历细节 / 平台 / 反方观点 / 结尾动作"这类环节时，**列出来问他要不要补进去**，不要自己默默跳过，也不要自己填一个。
- **说人话。** 问问题、报告诊断、给建议都用日常话，不要用"认知跃迁""价值闭环"这类词（他自己就不这么说话）。
- **诚实。** 没查到就说没查到；不确定就说不确定；他草稿有问题就直接指出来，不含糊其辞也不为了顺着他而美化。
