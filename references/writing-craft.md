# 写作工艺（全流程写作支持）

> 本文件在第七步写作时加载。把碎片化写作四步、文章骨架、论点深度、声音校准、结构接缝、句子与声音规则、起草规则、写作自检整合为模型可执行的写作支持流程。
>
> 纲领：**结构为骨，自由为魂，真诚为血，信噪比为气**。
>
> 边界：AI 协助写作，你保留最终写作权——定观点、定去留、定声音。AI 不编来源、不编事实、不把推测写成事实、不替你做判断。**Agent 按自己的理解写出一篇完整草稿，写进 `ai-draft.md`**；用户的草稿只读不写（文件名不限，Agent 只认第一步检测到的文件）——由用户决定是否采纳。

## 流程：碎片化写作四步

### 1. 捡骨头

先收素材，不急着成文。

- 把想法、引用、观察、数据随手记下，每条一句话，不组织不修饰。
- 能链接到既有笔记的，用双链 `[[笔记]]` 引入，避免重复定义。
- 事实性内容随手标 `[^N]` 溯源，记下来源链接。
- 不强迫一次写完；骨头够了再进入下一步。
- **模型角色**：帮你捕获碎片、链接既有笔记、标注来源、提醒哪些是推测。
- **不要做**：不要在这一步就把草稿写进用户的文件——你的草稿只写 `ai-draft.md`。

### 2. 搭建骨架

把骨头排成骨架，检查逻辑能否承载论点。

- 用文章骨架（见下）排章节。
- 每条支撑要点至少有一条推理链：证据 → 要点 → 核心论点。
- 检查标题层级连续、不跳级、不超三级。
- **模型角色**：提议骨架、标出逻辑漏洞、提醒哪节是"撑不起论点"的。
- **不要做**：不要替用户做"要不要这一节"的决定——可以按自己的理解写进草稿，但要说明你这么排的理由。

### 3. 组装完整

骨架成形后，**按自己的理解写出完整的散文草稿**，写进 `ai-draft.md`。

- 每一节明确：本节要回答什么问题、用什么证据、读完读者应该知道什么。
- 成篇标准：标题、开篇、正文、结尾齐全，读者能从头读到尾。
- **模型角色**：写出完整草稿，标出假设与需人确认处。
- **不要做**：不要把草稿写进用户的文件，也不要假装这是用户的定稿——它是你的版本，供用户取舍。

### 4. 持续完善

草稿成形后，进入句子与声音层的迭代。

- 一句一段地过，按句子与声音规则修。
- **先砍后修**：这一轮的首要动作是删——删冗余、删铺陈、删复述；砍完再谈润色。
- 反复回读，听声音是否一致。
- 把"感觉不对但说不出为什么"的句子单独拎出来，让模型帮你说清为什么不对。
- **模型角色**：迭代自己的 `ai-draft.md`，砍冗余、修句、提信噪比、统一声音、指出声音偏差。
- **不要做**：不要改动用户的文件；对用户草稿的意见写进「对你草稿的建议」。

## 文章骨架（你的真实结构）

按作者 cgartlab.com 已发表的实战文章（《碎片写作——建立一具思维标本》等）归纳：

1. **写作前自问**（3–5 个问题，成稿后删）：
   - 读者是谁？他现在相信什么？
   - 我一句话结论是什么？
   - 我为什么不同意主流？
   - 最小可交付是什么？
2. **一句话先说结论**：开头就给结论，不绕。
3. **开篇场景**：一个具体的时刻/画面，不是抽象概念。**场景必须有来源**（见下）。
4. **正文展开**：分节承载支撑要点，每节有推理链。
5. **收尾与最小可交付**：给读者一个能带走的具体动作或判断。
6. **AI 辅助披露**（如用 AI 辅助）：用 `> [!NOTE]` callout 标注使用了 AI 的部分。

> 不是每篇都要十节；"写作前自问 + 一句话结论 + 开篇场景 + 最小可交付" 四件尽量齐。

### 开篇场景的来源（硬规则）

**场景是最容易现编的地方，因为它读起来像文风，不像造假。**

"上周一个设计师朋友跟我说……"这种开头之所以好用，是因为它有画面。但那个画面是**作者的真实经历**。你没有它，就不能造一个同款的。

场景只有两种合法来源：

- **A 用户亲历**——他告诉过你这件事。按他说的写，**不补细节**（他没说的天气、神态、原话都不要加）。
- **B 可打开的公开来源**——一个真实报道、一次公开发言、一份记录。点得开链接。

**取不到场景时，换钩子，不要编场景。** 换成"问题"或"数据"钩子，或者直接从判断、材料说起。**没有场景的开头仍然是好开头**——直接给判断往往比一个来路不明的画面更干净。

> 需要用户提供经历时，最多问三句（做了什么 / 哪里出乎意料 / 现在怎样理解），见 `references/evidence-guide.md`。缺口标 `［请作者补：…］`，不要替他圆上。

## 论点深度（反浅）

浅的论点，读者看完标题就猜到了。深的论点反直觉、有机制、有可检验的推论。定论点与起草前用这六道测试过一遍：

1. **已知测试**：目标读者看完标题能猜到结论吗？能 → 太浅。
2. **机制测试**：你说了"为什么"，还是只说"是什么"？停在现象层就是浅。
3. **主流测试**：主流怎么说？你在哪一点不同意它？——用你骨架里的「我为什么不同意主流」。
4. **推论测试**：如果它成立，能推出什么别人没说的结论？推不出 → 它可能只是常识。
5. **具体测试**：宽到没人能反对（"沟通很重要"）= 浅。要具体到会被反驳。
6. **换框测试**：能否换掉问题本身？——不做"如何提高 X"，而问"X 是不是个伪问题"。

深度的真实来源是你自己的转折点：*我曾以为是 A，后来发现是 B*。从你的经验里挖这个转折，比堆理论更容易深。

> 深度 ≠ 复杂。深 = 反直觉 + 成立 + 有机制 + 有推论。绕口的术语不是深度，是伪装。

## 声音校准（像你，不像通用 AI）

通用 AI 有默认腔调：工整、对仗、四平八稳、面面俱到、"首先/其次/最后"。这与个人声音冲突。**宁可有毛边，不要工整的泛泛。**

起草前先取作者的声音指纹：

1. **取样**：读作者 3–5 篇已发表文章（`cgartlab.com` 或本地知识库）。
2. **提取特征**，写成可对照的清单（越具体越好，不要写"简洁"）：
   - 平均句长：一句话大概多少字？最长多少？
   - 段落长度：一段几句？
   - 人称：第一人称出现频率？"我"怎么用？
   - 常用句式：短句排比？破折号插入？反问？
   - 节奏：长句短句怎么交替？
   - 惯用词：有没有口头禅或反复出现的表达？
   - 开头习惯：场景切入，还是结论前置？
3. **起草时对照**：每起草一段，对照清单；偏离就改。
4. **并排测试**：把起草的句子和作者旧文的句子并排放，像同一个人写的吗？

已知的作者声音特征（起点，以实际语料为准）：

- 短句为主，节奏干脆
- 保留第一人称判断（"我认为 / 我不同意 / 我踩过这个坑"）
- 用具体场景开头（**场景必须是真实的**——见下方「开篇场景的来源」）
- 常用破折号「——」做转折与插入
- 不用空泛形容词与情绪词

> **注意**：这里提取的是**作者的写法**（他怎么起头、怎么断句），不是可以照抄的内容。作者的开篇场景来自他的真实经历；你没有他的经历，**不能模仿出一个同款的场景**——那正是「经历与事件」要拦住的东西。学他的节奏，不要学他的现场。

### 标点与词汇密度基线（数量型禁令的判据）

声音指纹不只管节奏，还要量出**密度**——所有"多不多"类的禁令都拿它当上限，不从零起算。

**实测基线**（2026-10 复测：25 篇 / 66,452 净汉字，cgartlab.com RSS 全文；周刊模板句已剔除。上一版为 2026-09 的 10 篇 / 26,215 字）：

| 指标 | 作者实测 | 参照 | 用法 |
|------|---------|------|------|
| 破折号 | **1.83 /千字**（篇间 0–8.45） | 人类 0.80、AI 2.38（lieflat） | 超过 1.83 才改，不从零起算 |
| 非引语冒号 | **4.65 /千字**（changelog 型两篇占大头） | — | 结构性标签放行，只清抬价式 |
| 引语冒号 | 0.08 /千字 | — | 正常放行 |
| 连词 | **2.25 /千字** | 常见阈值 7 | 远低于阈值，本就不必管 |
| 翻案腔 | **25 篇 0 处** | — | 作者本就不用 → 维持全禁（零成本） |

| 商业黑话 | 0.05 /千字（25 篇 3 处，全是「底层逻辑」） | — | 作者在用「底层逻辑」→ 按基线放行 |
| 借喻包装 | 0.06 /千字（25 篇 4 处比喻；另 15 处是字面用法） | — | 本义不受影响（实测证明该条款必要） |

**判读要点**：

- 会**削掉作者节奏**的规则（破折号、冒号）→ 按基线放宽。
- 作者**一次都不犯**的规则（翻案腔、说白了类、模型洞察路标、AI 占位）→ 维持全禁，零成本。
- **作者偶尔会用、且用法正当的**（名词化、换句话说、底层逻辑、显然、本质上）→ **不要整族禁掉**：按上表放行正当用法，只禁抬价式。这是 2026-10 复测修正的一处旧结论——上一版写"名词化作者本就不用"，实测 25 篇里有 4 处。
- 换一批新语料就重测，覆盖上表。**基线是活的，不是常量。**
- **短文别按比率算**。每千字指标在 500 字以下没有统计意义——500 字按 1.83/千字算期望只有 0.9 处，实际写 1 处或 2 处都属正常波动。短稿看**绝对数**（1–2 处），只有篇幅过千字才换算密度。

> **测量方法（别用正则直接下结论）**：字面子串匹配假阳性很高——「仓库」在写 GitHub / NAS 的文章里是**字面用法**（规则本就豁免），「颠覆性」会被「颠覆」重复计一次，「完成眼前的工作」根本不是名词化。上表是**逐条看上下文审计后**的结果。方法与原始数据见 `docs/research/ban-list-corpus-measurement.md`。

> **取不到语料时怎么办**：若离线、本地无作者语料、也拿不到已发表文章——明说"取不到声音样本，这版起草会比较通用，建议你用自己的句子替换"，不要假装有指纹，也不要静默退回通用腔。可让用户粘贴 2–3 句自己满意的旧句当样本。**密度基线同样退回默认值（即 AI 味），此时数量型禁令按清零执行。**
> 
> 起草完一段，用一句话自问："这段像作者写的，还是像 AI 写的？"像 AI 就重写，不要交。

## 第一稿怎么写（起草期正向清单）

与 SKILL.md 的禁用清单**成对**：那边讲"不要什么"，这边讲"该往哪写"。六条全部在**起草期**执行，不用等到改稿。

1. **开头尽快碰到事情。** 直答、讲刚发生的一幕，或从一个反常的小事实说起。**不预告全文结构**，不写"本文将从三个方面讨论"。
2. **一段先完成眼下这一件事。** 讲动作、补背景、算一笔账、解释原因、承认疑点或给出判断——一段挑一件。
3. **新段落必须带来新东西。** 新事实、新动作、新例子、新区别、新后果都算。**同一观点换个说法不算推进。**
4. **允许正常的重复、补充、自我修正和短暂岔话。** 这些是"像人"的来源，别为了干净把它们清掉。每一处都要来自眼前内容——**不能按固定间隔表演随意**，表演出来的随意是另一种模板。
5. **段落不必等长。** 复杂的地方多说两句，讲明白的很快就过。单句成段只留给确实需要停一下的地方。
6. **不要先给结构命名。** 除非用户明确要清单或教程，别一上来就把题目拆成"三个层次、四个阶段"。**分类应当来自材料，不能拿分类代替文章。**

> 第 1、2、3、5 条与下面的句子级规则是同一件事的两层：这组管段落怎么搭，句子级管一句话怎么写。第 4 条是禁用清单的反面——**禁令管住 AI 的套式，许可保住人的毛边**，缺一条就只剩减法。

## 句子级规则

通用 AI 在句子层面的毛病有明确规律。以下规则可在起草和自检时逐条对照。

### 1. 主干先出来

先说谁做了什么，再补时间、原因和条件。读者要尽早知道句子的主角。

- 长定语拆成短分句：「经历了长达数年缺乏稳定收入来源的反复尝试后，终于促使他改变方向的，是一次来自老同事的邀请」→「他折腾了几年，一直没挣到稳定的钱。后来老同事找过来，问他愿不愿意一起做项目，他才换了方向。」
- 一句话里出现四个以上的「的」，先找真正做事的人，把他放到前面。
- 英语式层层嵌套搬到「的」字前面 → 拆成小句，让动作和结果顺着走。

### 2. 顺势接话

汉语常常先交代一个人做了什么，再沿着刚出现的人、物或结果继续说。

- 前一句把某物送到句尾，后一句顺手接住它。
- 指向清楚时可以省去重复的主语和机械连接词；两个人同时在场、前一句出现多个名词或中间插入一大段话时，把名字写回来。
- 示例：「他走到门口，又折回来。那张药盒在抽屉里——他数过，还剩七天。」

### 3. 长短句有高低差

真人不会把每段修成同样长度。

- 十个字的句子可以挨着四十个字的句子，不要每段都在同一个位置停。
- 连续短句像敲桌子，连续长句让人一直等不到落脚处。读出声，哪里需要回头找主语、哪里一口气读不完，都要改。
- 一段超过五句考虑拆开，但不要为了拆而拆——一段讲一件事就够了。

### 4. 少用连词

模型每两句就要用一个连词，中文小句靠语序和事理自己会接。

- 删掉一半连词试试：「因为店里生意不好，所以他决定把下午的时间用来学修表，同时也能多一门手艺」→「店里生意不好，他下午闲着，就学起了修表，多一门手艺总没坏处。」
- 「因为 / 所以 / 但是 / 同时 / 此外 / 而且 / 并且 / 因此」密度超过每千字 7 个就偏了。

### 5. 名词还原

动词被压成名词 = 模型腔。

- 「进行了调整 → 改顺了」「实现了增长 → 多挣了多少」「完成了对流程的优化 → 把流程改好了」
- 看到「进行 / 实现 / 完成 / 开展」带着一个动名词，还原成直接的动作。
- 「提升用户留存 → 让用户多来一次」「推进数据治理 → 把数据理顺了」

### 6. 允许重复

人不怕重复，模型怕重复。

- 一段里「修表」可以出现四次；模型第二次就换成「这门手艺」，第三次换成「这项技能」，换来换去文章会油。
- 该重复就重复，不要换着花样找同义词。

### 7. 知识按需出现

背景、制度、数字都可以写，但先问眼前这段为什么需要它。

- 一段背景若能解释人物为什么只能这样选、能改变风险大小、能推翻一个直觉、能让后面的结果变得可懂 → 放进来。
- 只证明作者知道很多、删掉不影响理解 → 删掉。
- 不要先把背景一次倒完。读者问到钱，算钱。人物碰到一条制度，再解释制度。

### 8. 说到能接住就停

动作、物件、原话和前后变化已经传出情绪时，不要紧跟一句解释。

- 「他把一周的药分进七个小格。走到门口，他又回来，把星期三那格打开看了一遍。」——已经能感到牵挂，不需要再补「他很担心母亲记错药」。
- 比喻落下以后，不要马上翻译它的含义。读者能自己走完的两三步，留给读者。
- 留白不能藏掉关键事实、人物选择和因果，只省去读者已经能得到的解释。

### 9. 判断从正面下

- 不要先摆一个笨答案，再宣布自己看到了更深处。直接把事实差异讲出来。
- 不要为了显得周全，把每个方向都照顾一次。
- 不要按固定间隔表演随意——岔话要来自眼前内容，不是按模板加调味。
- 判断可以偏、可以有情绪。把依据放在附近，让读者知道这是作者的看法。

### 10. 白话打底，古意看场合

自然白话是根。先选说话者平时会用、读者一眼能懂的词。

- 单音节往往更近口语，双音节往往更正式：「买 / 购买」「改 / 修改」「看 / 观察」「用 / 使用」。根据说话者和场合选——不要为了稳重整篇换长词，也不要为了古朴强行把双音节压成单字。
- 「天快亮了，他还没回家」本身就是好中文。「天将明，人未归」更紧，也把语气推远——周围的文章承得住这种距离时才用。
- 成语和典故只在三个条件同时成立时留下：意思准确、普通读者不用查、放进去比白话更省。需要另起一句解释的典故，说明它没有真正进入文章。
- 古意还可以来自照应和收束：前文反复写雨，到结尾只说「雨还没停」，已经够了。不要临时请一句古诗替全文盖章。

### 11. 具体细节必须有工作

好细节会改变理解：一笔价格说明风险，一段原话说明关系，一次失败说明旧办法为何行不通，一个地名解释人物为何只能那样选。

装饰性细节只负责让画面显得真实。**「凌晨三点、第三根烟、桌上的冷咖啡、窗外的雨」——没有来源也没有改变后文，全部不要。** 假细节越具体，AI 味越重。

> **假细节不只是"AI 味"，它是编造。** 「凌晨三点」是一个关于现实的主张——谁在凌晨三点做了什么。它和编一篇不存在的文献是同一类错误，只是更隐蔽：文献有格式可查，细节没有。**细节越具体，读者越会当真，所以它越具体越危险。**
> 写不动的时候，正确动作是**回到材料**或**留白**，不是补一个画面。完整规则见 `references/evidence-guide.md` 的「经历与事件的核实」。

> 以上规则与 SKILL.md「禁用清单」配合使用。SKILL.md 管禁止，本文件管怎么做。

## 篇章推进（按局部问题往前走）

长文可以有总方向，不需要预先搭一副起承转合的架子。**写完一段，只问一句：读者现在最想知道什么。**

| 你先讲了 | 读者会追问 |
|---------|-----------|
| 发生了什么 | 为什么 |
| 一个判断 | 你凭什么这样想 |
| 一个人的处境 | 他后来怎么办 |
| 通常情况 | 眼前这次哪里特殊 |
| 结果 | 中间到底出了什么岔子 |

这些关系可以反复交替，不要排成固定的五段。

- **推进靠材料和因果，不靠路标**：删掉「更深一层」「真正的问题」「还有一点」，让事实差异与读者问题承担连接。
- **岔话要从眼前的词长出来**：讲一个人的借款，顺手解释当时民间借贷怎样催收，解释完继续讲这笔钱——它有用。讲到借款忽然想起文明兴衰，通常只是在炫耀联想能力。
- **绕出去要带东西回来**：回来时多一件证据、一个尺度、一个反例，或者作者终于承认先前想错了。出去一圈原来的判断纹丝不动，这段多半只是知识展览。

## 判断要带着来路与边界

判断可以尖锐，也可以有偏见，但前文要让读者看到它从哪里来。

- **先把反方最有力的理由讲准确**，再说当前材料下更相信哪种解释。不要先摆一个笨答案再推翻它。
- **材料支持七成，就说到七成**。剩下三成承认不知道，通常比再补五个限定词更可信。
- **边界说明一次就够**。每句话都加「可能 / 或许 / 不能排除」，作者会从文章里消失。
- **建议要带成本和适用条件**。商业、医疗、法律与金融内容要区分一般信息、证据结论和针对个人的建议。
- 重要例外只讲会改变结论的那几个，不要为了周全把每个方向都照顾一次。

### 数字写完继续走一步

核对时间、单位、样本、口径和比较对象——**百分比与百分点分开**。然后不要停在数字上：

- 这个数字会让**谁**多花多少时间、少付多少钱、增加哪种选择，或受到什么限制？
- **一个案例只能说明一角**，不能自动代表整个行业。
- 判断市场很大以前，先找最早愿意付钱的人、他眼下的麻烦和第一道限制。

数字后面接上"所以对读者意味着什么"，否则它只是背景装饰。

### 没有亲历时的范围纪律

用户没提供经历、你自己也没有可核实的亲历时，最容易写出一种模型稿：开头提出完整论点，接着把原因分成六七类，每段补一个限定，结尾再总结一遍。它可能全都对，读者仍然碰不到任何东西。

- **只抓当前最有把握的一两个原因。文章不必包办整个问题。**
- 有可靠流程材料时，可以选一个普通角色，把他从开始到结果的动作走一遍——必须明确这是常见情形，不能配上伪造的精确经历。
- 一段抽象解释以后，尽快落到一次报价、一份作品、一项支出、一次失败或一个决定。
- 手里只有三条抽象材料，不能把每条换四种说法写成十二段（见 SKILL.md 第一步半）。

> 论坛里的好回答经常不完整，但有一块讲得很透。机构稿才需要面面俱到。

## 写给眼前这个读者

**不要同时向"所有人"演讲。** 把读者想成一个聪明、感兴趣、对背景不熟的普通人：讲到他已经明白就往下走，讲到他可能误会就多补半句。

- 向读者说话不等于频繁喊"大家""朋友们"——真正的交流发生在**解释顺序**里，不在称呼里。
- 知乎回答前面天然有一个问题，公众号文章也要在心里补出一个读者：他刚知道什么，接下来会问什么。
- 每写完一段问一次：**读者知道上一段以后，最自然会追问什么？**（见「篇章推进」）

## 幽默来自降格

一个宏大的说法碰到现实里的小麻烦，天然会好笑。把那个落差写出来就够了。

- 可以拿自己开刀，可以承认当时犯蠢，也可以对一个被吹得太大的概念不太客气。
- **笑点落下以后继续讲事，别停下来解释为什么好笑。**
- 不要规定每几百字来一次吐槽，也不要借粗口证明作者是活人。

## 结构接缝（合并 · 顺序 · 承接）

接缝问题有两类：**跳**（缺承接，读者断线）和**碎**（该并没并，一节只有半个主张）。判据：

1. **合并测试**：相邻两节讲同一个主张吗？是 → 合并。两节各只半个主张 = 该合成一节。
2. **独立测试**：这一节删掉，文章会缺一块吗？不会 → 删或并。
3. **顺序测试**：交换相邻两节，逻辑更顺吗？更顺 → 重排。
4. **承接测试**：上一节末尾接下一节开头，会断线吗？会 → 加一句**真承接**（点明两节关系）或重排；不要用废话过渡。
5. **层级测试**：同级标题是不是同级的事？一个小点不该和主论点并排。
6. **一节一主张**：一节两个主张 → 拆；两节各半个 → 合。

> 承接要交代**关系**（因果 / 对比 / 递进 / 让步），不是交代**流程**（"接下来""然后""说完了 A 我们看 B"）。
> 没有关系可交代时，直接硬切——硬切比假过渡干净。

上面的「句子级规则」讲**怎么做**；**禁止什么**以 SKILL.md「风格与禁用（硬规则）」为唯一事实源，本文件不再重复——两处定义同一条规则必然漂移。

排版类细则（中英文间空格、直角引号、图片语法等）见 `references/sspai-format.md`（面向少数派时）；非少数派场景沿用作者既有习惯。

## 起草规则（写 Agent 草稿时）

Agent 按自己的理解写出一篇完整草稿，写进 `ai-draft.md`（不写用户的草稿）。以下规则作用于这篇草稿。

**第一条：默认交最短版本。**

AI 天然倾向铺陈，用户需要的是减法。所以起草的默认是"删到不能再删"——**让用户加，而不是让用户删**。给太多比给太少更糟：多余的字要用户花力气清理，而"信噪比为气"是这个 skill 的纲领。

**起草后先自己砍一遍（逐句删除测试）**：

- 删掉这句，读者会损失信息吗？不会 → 删。
- 这句只是换了说法重复上一句吗？是 → 删。
- 这句在为后面铺垫、做过渡、做总结吗？是 → 删（除非它本身承载新信息）。

**长度预算**：

- 一段不超过 5 句；超过就先砍到 5 句再交。
- 一个支撑要点不超过 1 段。
- **不自己加"总结段"**——结论开头已说过，不在结尾复述。
- 只写这篇文章，不顺手把系列里的其他篇也写了。
- **草稿写成一篇，不要写成"建议清单"**——读者（用户）应该能从头读到尾，而不是读一堆待办。

**不许铺陈（AI 味填充词，一律不写）**：

- 铺垫过渡：值得注意的是 / 不难看出 / 说到这里 / 换句话说 / 从某种意义上说 / 不可否认 / 众所周知
- 空洞总结：综上所述 / 总而言之 / 这说明了…的重要性 / 这为我们提供了一个…的视角 / 归根结底
- 过度对冲：在某种程度上 / 或多或少 / 在大多数情况下 / 可以说 / 在一定程度上
- 三段式排比堆砌（"不仅…而且…更…"）——除非三者都承载独立信息
- 复述式收尾（把刚说过的换个说法再说一遍）

**起草前先做两件事**：

- 过一遍「论点深度」六道测试（别把常识当论点交出去）。
- 取作者声音指纹（见「声音校准」），起草时对照。

**仍然保留的诚实规则**：

- 用具体例子和场景，不用抽象概括。
- 推测显式标注「（推测，需核实）」；不确定的来源标「（来源待核实）」。
- 起草后一句话说明"我假设了 X"以及"哪几句你砍掉也不损失信息"——让用户容易做减法。
- 不替用户做"要不要这一段"的决定——只起草到 `ai-draft.md`，由用户决定采纳与否。

## 写作自检（草稿完成后）

### 多遍改稿框架

初稿写完后按顺序过以下六遍。每一遍只专注一件事，不要交叉。

**第一遍 — 看谁在说**
- 现实稿：作者凭什么知道这件事？哪一处能看出他真的在意？
- 哪个判断有材料托着，哪个判断没有？没有的删掉或补材料。
- 不要靠增加「我觉得」「说真的」来修复匿名感——声音来自取舍，不来自代词。

**第二遍 — 看文章怎样往前走**
- 给每段标一个主要作用：动作、事实、解释、例子、判断、背景或情绪。
- 连续几段只做同一件事 → 合并或删除。
- 每段的新东西：是事实、动作、例子，还是判断？如果一段只把前段换一种说法 → 合并。
- **给每段标一个不公开的材料出处**（用户材料 / 公开来源 / 可核验流程）。只能写出"这是进一步解释"或"这是可能的影响"，说明这一段没有新东西。
- 做一次压缩试验：删掉三分之一以后，事实、动作、判断几乎没变 → 原稿在注水，保留删短后的版本。

**第三遍 — 拆表演性中文**

按下面五类逐个圈，不要只按字面查。

- **假深刻**：圈出所有单独截图很好看、放回正文却没有增加事实、解释或情绪的句子，大部分删掉。连续几段都用一句短判断收尾 → 只留最有材料的一处，普通段落回到普通句子。
- **假具体**：搜索精确时间、天气、神态、房间摆设、烟酒食物和突然出现的原话。逐项问它来自哪里、会不会改变后文——没有来源也没有作用，删掉。
- **假口语**：「老铁」「兄弟们」「咱就是说」「泡杯茶慢慢说」。只有当前说话者真会这样说时才留。不要为制造活人感主动加粗口、错别字、三连省略号和括号吐槽。
- **抽象名词**：抽象名词连续出现时，问清谁做了什么、影响了谁、钱与时间与责任落在哪里。**一句话能换进十篇商业文章，说明它没有当前材料。**
- **比喻换场**：现代现实散文先把借来的世界写在旁边——道路、战争、建筑、温度、仓储、海洋、身体。短距离出现三套时先全部还原成本义；本义已经清楚，一个也不必放回。

再加字面清理：

- 搜翻案腔变形（见 SKILL.md 禁用清单），逐段问：是不是先立了一个读者并没有的误解、再推翻它？
- 搜三项以上同构排比 → 留两项，第三项换说法或删掉。
- 搜名词化 → 还原成直接的动词。
- 搜「说白了 / 说穿了 / 先说结论」→ 全部删除或改写。
- 搜模型洞察路标 → 给段落抬价的全部删除。

**第四遍 — 听一遍中文顺不顺**
- 读出声。逗号处还能接着说，句号处已经落下一件事。
- 连续短句像敲桌子 → 合并；长句一口气没有落脚处 → 拆开。
- 连续出现三个以上的「的」→ 重写。
- 检查「买 / 购买」「改 / 修改」「看 / 观察」这类单双音节词，根据说话者和场合选，不要全换成正式长词。
- 成语、典故和文言句单独拿出来读，删掉以后更自然就删。

**第五遍 — 清禁用项**

> **改法只有一条**：先找回这句**原本想说的事实**，再用普通句子说出来。**不要去找另一个"漂亮句式"替换**——那只会换上更工整的套话，把僵硬加重一遍。找不回事实就删，不要补一个没依据的说法。

- 破折号与冒号**按作者基线量一遍**（见「标点与词汇密度基线」）：超量的减到基线以内，抬价式冒号（"一句话总结："）全部改写；未超量的留着。无语料时才清零。
- 搜索三项以上的同构排比、抽象抒情、名词化 → 清零。
- 搜索黑话 → 改成人、动作、钱、时间与后果。
- 搜索抒情词给抽象概念穿衣服 → 删掉。

**第六遍 — 查结尾**
- 最后两段分别删掉再读。删掉更有力 → 让文章提前结束。
- 最后一段重新概括全文 → 先删掉，前文已经讲明白的内容不需要再证明一次。
- 搜索结尾的「时代 / 文明 / 未来 / 世界 / 历史 / 奇迹 / 所有人 / 全人类」→ 正文没持续处理这个尺度就删掉。

> 改稿目标不是把文章修到无懈可击，而是先保护已经活着的地方，再拆掉模型摆出来的姿势。

### 最后冷读

暂时忘掉所有规则，只回答下面几句——回答不上来的地方就是问题所在。

- 哪里让我相信作者确实知道这件事？
- 哪里让我愿意继续读？
- 哪一段像人在处理一个问题，哪一段像模型在完成写作任务？
- 哪句话说得比材料大？
- 文章在哪一句已经结束？

### 可量化自检（模型目测，不跑脚本）

下面几项有明确的**形状**，用判断数一遍就能发现。命中不等于必须改——先判断它是不是当前材料与文体真正需要的。

| 症状 | 判据 | 动作 |
|------|------|------|
| **相邻句结构同款** | 连续两三句**逗号数量相同 + 成分顺序相同 + 收尾方式相同** | 单看每句都通顺，连起来像在填表。挑一句换骨架 |
| **段落可交换** | 挑两段对调，读起来没差别 | 说明写的是要点罗列不是论证。重写承重关系 |
| **空转句引列表** | 「这一点体现在以下几个方面」之后跟一个清单 | 引导句没承载信息，删掉 |
| **具体指称密度低** | 通篇找不到可核验的具体指称（数字 / 日期 / 金额 / 时长 / 人名 / 型号 / 原话） | 材料稀薄是整篇的底色。补材料，不是补形容词 |
| 连词太多 | 超过**作者基线**（实测 2.25 /千字），常用阈值 7 /千字 | 删到基线以下，读不断的地方不用补回来 |
| 长前置成分多 | 反复出现「在……之后，」「那些……的……，」「真正让……的，是」 | 把做事的人提到前面，原因与条件接到后面 |
| 重定语句 | 一句话四五个「的」，读到名词时已忘了句首 | 拆成小句，先让人和东西出现 |
| 段落开场重复 | 四段以上用「其实 / 不过 / 当然 / 所以 / 但是」开头 | 换开场，或把其中几段并进上一段 |
| 段落过度单一 | 可识别段落中 75% 以上只有一句话 | 合并能顺着读下去的部分 |
| 连续短促单句段 | 连续四个以上二十来字的单句段 | 检查是不是在排队喊结论——合并或删 |
| 借喻聚集 | 八百字内出现三套借喻（道路 / 战争 / 建筑 / 温度 / 仓储 / 海洋 / 身体） | 全部还原成本义；本义已够清楚，一个也不必放回 |
| 金句过密 | 「」括起的短语超过每七百字三处 | 多半在批量造金句，拆掉 |
| 洞察路标超量 | 「真正 / 本质上 / 更深层次 / 归根结底 / 关键在于」超过每九百字两处 | 删掉抬价的那几个 |

> **已移除「句长变异系数」**（2026-09 复核后删除，替换为上表首行的「相邻句结构同款」）。
>
> 依据：[lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone) 的 300 篇中文 AI 样本对照实验（5 个模型各 60 篇，话题与文体跟人类语料对齐）。该研究**自己推翻过这条**：初测得出「AI 句长均匀度是人类 50 倍」，扩大语料后查明是**切句缺陷造成的假象**——复测 AI 句长 CV 0.58、人类 0.67，实为 0.87 倍；段落离散度 0.94 倍；文末专列「六次测量失误」。
>
> 另一来源 [rossmann](https://github.com/realrossmanngroup/no_ai_slop_writing_rules) 支持保留句长方差，但其语料是**单一作者的技术维修博客**（均长 2.1 句/段），寄存器特殊，不足以推翻中文测量。
>
> **长短句有高低差作为写作意图仍然保留**（见「句子级规则」第 3 条）——只是不再当作 AI 味的证据去扣分。**毛边是写出来的结果，不是改出来的手段。**
>
> 这些检查只负责**发现形状，不能判断文章有没有人**。形状干净但没人味，仍然是失败稿——回到「最后冷读」。
> 诗歌、剧本、对白与实验写作只执行事实边界与用户明确要求，散文形状检查服从具体文体（见 `references/form-guide.md`）。

### 自检逐项检查

读回用户的草稿（只读，第一步检测到的文件名）与你的 `ai-draft.md`，逐项过：

- **可删性**：有没有一句删掉不损失信息？有 → 删。
- **论点深度**：用「论点深度」六道测试——有没有停在常识层？
- **声音校准**：对照声音指纹——有没有一句像通用 AI 而非作者？
- **结构接缝**：用「结构接缝」六道测试——该并没并、该拆没拆、有没有断线？
- **证据充分性**：每条核心主张有来源吗？二手当一手了吗？
- **逻辑漏洞**：推理链站得住吗？范围反例、价值反例呢？
- **骨架塌陷**：标题层级连续吗？哪节撑不起论点？
- **信噪比**：哪句是空泛情绪词？哪句是铺垫/过渡/空洞总结？哪句是 AI 占位文本？

对每条偏差，给出可执行修改建议（不是"再想想"）。

## 与第八步（反驳）的区别

- **写作自检**（本文件）：草稿完成后，检查草稿自身的声音、证据、逻辑、骨架、信噪比——向内找问题。
- **反驳**（SKILL.md 第八步）：草稿完成后，主动找外部反例反驳草稿——向外找反证。
- 两步都做，自检在前，反驳在后。
