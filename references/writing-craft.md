# 写作工艺（全流程写作支持）

> 本文件在第七步写作时加载。把碎片化写作四步、文章骨架、论点深度、声音校准、结构接缝、句子与声音规则、起草规则、写作自检整合为模型可执行的写作支持流程。
>
> 纲领：**结构为骨，自由为魂，真诚为血，高信噪比为气**。
>
> 边界：AI 协助写作，你保留最终写作权——定观点、定去留、定声音。AI 不编来源、不编事实、不把推测写成事实、不替你做判断。Agent 的所有草稿、骨架、提议、修句写进 `ai-draft.md`；用户的草稿只读不写（文件名不限，Agent 只认第一步检测到的文件）——由用户决定是否采纳。

## 流程：碎片化写作四步

### 1. 捡骨头

先收素材，不急着成文。

- 把想法、引用、观察、数据随手记下，每条一句话，不组织不修饰。
- 能链接到既有笔记的，用双链 `[[笔记]]` 引入，避免重复定义。
- 事实性内容随手标 `[^N]` 溯源，记下来源链接。
- 不强迫一次写完；骨头够了再进入下一步。
- **模型角色**：帮你捕获碎片、链接既有笔记、标注来源、提醒哪些是推测。
- **不要做**：不要在这一步就生成完整段落或结论。

### 2. 搭建骨架

把骨头排成骨架，检查逻辑能否承载论点。

- 用文章骨架（见下）排章节。
- 每条支撑要点至少有一条推理链：证据 → 要点 → 核心论点。
- 检查标题层级连续、不跳级、不超三级。
- **模型角色**：提议骨架、标出逻辑漏洞、提醒哪节是"撑不起论点"的。
- **不要做**：不要替你做"要不要这一节"的决定。

### 3. 组装完整

骨架成形后，把每一节的目标、要点、证据位置补齐，但散文仍由你写。

- 每一节明确：本节要回答什么问题、用什么证据、读完读者应该知道什么。
- 标记哪一节是主论点的支柱，哪一节是背景/过渡。
- **模型角色**：起草每一节的"目标 + 要点 + 证据位置"占位，标出需要人补的地方。
- **不要做**：不要直接生成完整散文段落冒充你的声音。

### 4. 持续完善

骨架稳定后，进入句子与声音层的迭代。

- 一句一段地过，按句子与声音规则修。
- **先砍后修**：这一轮的首要动作是删——删冗余、删铺陈、删复述；砍完再谈润色。
- 反复回读，听声音是否一致。
- 把"感觉不对但说不出为什么"的句子单独拎出来，让模型帮你说清为什么不对。
- **模型角色**：砍冗余、修句、提信噪比、统一声音、指出声音偏差。
- **不要做**：不要重写整段替换你的判断。

## 文章骨架（你的真实结构）

按作者 cgartlab.com 已发表的实战文章（《碎片写作——建立一具思维标本》等）归纳：

1. **写作前自问**（3–5 个问题，成稿后删）：
   - 读者是谁？他现在相信什么？
   - 我一句话结论是什么？
   - 我为什么不同意主流？
   - 最小可交付是什么？
2. **一句话先说结论**：开头就给结论，不绕。
3. **开篇场景**：一个具体的时刻/画面，不是抽象概念。
4. **正文展开**：分节承载支撑要点，每节有推理链。
5. **收尾与最小可交付**：给读者一个能带走的具体动作或判断。
6. **AI 辅助披露**（如用 AI 辅助）：用 `> [!NOTE]` callout 标注使用了 AI 的部分。

> 不是每篇都要十节；"写作前自问 + 一句话结论 + 开篇场景 + 最小可交付" 四件尽量齐。

## 论点深度（反浅）

浅的论点，读者看完标题就猜到了。深的论点反直觉、有机制、有可检验的推论。定论点与起草前用这六道测试过一遍：

1. **已知测试**：目标读者看完标题能猜到结论吗？能 → 太浅。
2. **机制测试**：你说了"为什么"，还是只说"是什么"？停在现象层就是浅。
3. **主流测试**：主流怎么说？你在哪一点不同意它？——用你骨架里的「我为什么不同意主流」。
4. **推论测试**：如果它成立，能推出什么别人没说的结论？推不出 → 它可能只是常识。
5. **具体测试**：宽到没人能反对（"沟通很重要"）= 浅。要具体到会被反驳。
6. **换框测试**：能否换掉问题本身？——不做"如何提高 X"，而问"X 是不是个伪问题"。

深度的真实来源是你自己的转折点：*我曾以为是 A，后来发现是 B*。从你的经验里挖这个转折，比堆理论更容易深。

> 深度 ≠ 复杂。深 = 反直觉 + 成立 + 有机制 + 有推论。绕口的术语不是深度，是伪装。

## 声音校准（像你，不像通用 AI）

通用 AI 有默认腔调：工整、对仗、四平八稳、面面俱到、"首先/其次/最后"。这与个人声音冲突。**宁可有毛边，不要工整的泛泛。**

起草前先取作者的声音指纹：

1. **取样**：读作者 3–5 篇已发表文章（`cgartlab.com` 或本地知识库）。
2. **提取特征**，写成可对照的清单（越具体越好，不要写"简洁"）：
   - 平均句长：一句话大概多少字？最长多少？
   - 段落长度：一段几句？
   - 人称：第一人称出现频率？"我"怎么用？
   - 常用句式：短句排比？破折号插入？反问？
   - 节奏：长句短句怎么交替？
   - 惯用词：有没有口头禅或反复出现的表达？
   - 开头习惯：场景切入，还是结论前置？
3. **起草时对照**：每起草一段，对照清单；偏离就改。
4. **并排测试**：把起草的句子和作者旧文的句子并排放，像同一个人写的吗？

已知的作者声音特征（起点，以实际语料为准）：

- 短句为主，节奏干脆
- 保留第一人称判断（"我认为 / 我不同意 / 我踩过这个坑"）
- 用具体场景开头（"上周一个设计师朋友跟我说…"）
- 常用破折号「——」做转折与插入
- 不用空泛形容词与情绪词

> **取不到语料时怎么办**：若离线、本地无作者语料、也拿不到已发表文章——明说"取不到声音样本，这版起草会比较通用，建议你用自己的句子替换"，不要假装有指纹，也不要静默退回通用腔。可让用户粘贴 2–3 句自己满意的旧句当样本。
> 
> 起草完一段，用一句话自问："这段像作者写的，还是像 AI 写的？"像 AI 就重写，不要交。

## 结构接缝（合并 · 顺序 · 承接）

接缝问题有两类：**跳**（缺承接，读者断线）和**碎**（该并没并，一节只有半个主张）。判据：

1. **合并测试**：相邻两节讲同一个主张吗？是 → 合并。两节各只半个主张 = 该合成一节。
2. **独立测试**：这一节删掉，文章会缺一块吗？不会 → 删或并。
3. **顺序测试**：交换相邻两节，逻辑更顺吗？更顺 → 重排。
4. **承接测试**：上一节末尾接下一节开头，会断线吗？会 → 加一句**真承接**（点明两节关系）或重排；不要用废话过渡。
5. **层级测试**：同级标题是不是同级的事？一个小点不该和主论点并排。
6. **一节一主张**：一节两个主张 → 拆；两节各半个 → 合。

> 承接要交代**关系**（因果 / 对比 / 递进 / 让步），不是交代**流程**（"接下来""然后""说完了 A 我们看 B"）。
> 没有关系可交代时，直接硬切——硬切比假过渡干净。

## 句子与声音规则

通用写作硬规则（声音 / 事实 / 禁用清单）以 **SKILL.md「风格与禁用（硬规则）」为准**，本文件不再重复——两处定义同一条规则必然漂移。

排版类细则（中英文间空格、直角引号、图片语法等）见 `references/sspai-format.md`（面向少数派时）；非少数派场景沿用作者既有习惯。

## 起草规则（模型代起草时）

当用户明确要求模型起草某段时，把起草内容写进 `ai-draft.md`（不写用户的草稿）。

**第一条：默认交最短版本。**

AI 天然倾向铺陈，用户需要的是减法。所以起草的默认是"删到不能再删"——**让用户加，而不是让用户删**。给太多比给太少更糟：多余的字要用户花力气清理，而"高信噪比"是这个 skill 的纲领。

**起草后先自己砍一遍（逐句删除测试）**：

- 删掉这句，读者会损失信息吗？不会 → 删。
- 这句只是换了说法重复上一句吗？是 → 删。
- 这句在为后面铺垫、做过渡、做总结吗？是 → 删（除非它本身承载新信息）。

**长度预算**：

- 一段不超过 5 句；超过就先砍到 5 句再交。
- 一个支撑要点不超过 1 段。
- **不自己加"总结段"**——结论开头已说过，不在结尾复述。
- 只起草用户要求的那一部分，不顺手把别的节也写了。

**不许铺陈（AI 味填充词，一律不写）**：

- 铺垫过渡：值得注意的是 / 不难看出 / 说到这里 / 换句话说 / 从某种意义上说 / 不可否认 / 众所周知
- 空洞总结：综上所述 / 总而言之 / 这说明了…的重要性 / 这为我们提供了一个…的视角 / 归根结底
- 过度对冲：在某种程度上 / 或多或少 / 在大多数情况下 / 可以说 / 在一定程度上
- 三段式排比堆砌（"不仅…而且…更…"）——除非三者都承载独立信息
- 复述式收尾（把刚说过的换个说法再说一遍）

**起草前先做两件事**：

- 过一遍「论点深度」六道测试（别把常识当论点交出去）。
- 取作者声音指纹（见「声音校准」），起草时对照。

**仍然保留的诚实规则**：

- 用具体例子和场景，不用抽象概括。
- 推测显式标注「（推测，需核实）」；不确定的来源标「（来源待核实）」。
- 起草后一句话说明"我假设了 X"以及"哪几句你砍掉也不损失信息"——让用户容易做减法。
- 不替用户做"要不要这一段"的决定——只起草到 `ai-draft.md`，由用户决定采纳与否。

## 写作自检（草稿完成后）

读回用户的草稿（只读，第一步检测到的文件名）与你的 `ai-draft.md`，逐项过：

- **可删性**：有没有一句删掉不损失信息？有 → 删。
- **论点深度**：用「论点深度」六道测试——有没有停在常识层？
- **声音校准**：对照声音指纹——有没有一句像通用 AI 而非作者？
- **结构接缝**：用「结构接缝」六道测试——该并没并、该拆没拆、有没有断线？
- **证据充分性**：每条核心主张有来源吗？二手当一手了吗？
- **逻辑漏洞**：推理链站得住吗？范围反例、价值反例呢？
- **骨架塌陷**：标题层级连续吗？哪节撑不起论点？
- **信噪比**：哪句是空泛情绪词？哪句是铺垫/过渡/空洞总结？哪句是 AI 占位文本？

对每条偏差，给出可执行修改建议（不是"再想想"）。

## 与第八步（反驳）的区别

- **写作自检**（本文件）：草稿完成后，检查草稿自身的声音、证据、逻辑、骨架、信噪比——向内找问题。
- **反驳**（SKILL.md 第八步）：草稿完成后，主动找外部反例反驳草稿——向外找反证。
- 两步都做，自检在前，反驳在后。
